# AI techniques in DuitDuit

What each technique does, where it lives, how it is checked, and what it does not claim. The demo company's data is synthetic; any figure measured on it is labelled as such. Figures for real companies are **not measured** until a company's own records exist.

| Technique | What it does | Code | Checked by |
| --- | --- | --- | --- |
| Retrieval-augmented answers (RAG) | Answers cite their sources (SOURCE-n). Exact identifiers are matched first; otherwise vector search over protected text, then a BM25 keyword rerank fused with the vector order by reciprocal rank fusion. Only records that contain a question word get keyword credit | `app/services/retrieval.py` (`retrieve_hybrid_hits`, `rerank`) | `tests/test_grounding.py` |
| Grounding check | Each sentence of an answer is checked against the sources it cites: every figure must appear, and at least half of its content words. The result (sentences, supported, which ones are not) is returned with the answer. Lexical, not a model judging a model: it can miss a correct paraphrase, but it cannot be talked into passing an invented figure | `app/services/grounding.py` | `tests/test_grounding.py`, `ADV-24` |
| Personal-data detection (NER) | GLiNER plus deterministic patterns find names, contacts and identifiers before any text reaches a model | `app/security/detect.py` | existing detection tests |
| Payment-delay model (machine learning) | Learns each customer's usual lateness and the spread of its slow payments from paid e-invoices (median and 90th percentile), shrunk towards the company-wide figure by empirical Bayes so a customer with three invoices does not decide everything. The forecast's worst case for an invoice uses the customer's spread. A leave-one-out backtest reports how often a past invoice landed inside its predicted worst case | `app/services/payment_model.py`, `app/services/cash_basis.py` | `tests/test_payment_model.py` |
| Calibrated forecast ranges (conformal prediction) | Once a horizon has five scored days, the likely balance ± the ceil((n + 1) × 0.8)-th smallest past miss is a range that held at least 80% of the time on the company's own days, with no assumption about the error distribution | `app/services/forecast_check.py` | `tests/test_forecast_check.py` |
| Anomaly detection (robust statistics) | Flags an open bill far from its supplier's usual amount (modified z-score with median and median absolute deviation, above 3.5), a possible duplicate bill, a large first bill from a new supplier, and two equal payments to one payee within three days. Each flag gives its reason in numbers; a person can send it to the review inbox | `app/services/anomalies.py` | `tests/test_anomalies.py`, `F23` |
| Checker agent (multi-agent) | A second, deterministic agent checks every review item against company policy before a person decides: evidence present, the owner escalation amount, the two-person rule for payments, holds on the invoice, and anomaly flags. It adds findings and cannot approve, reject or change anything | `app/services/policy_checks.py` | `tests/test_policy_checks.py`, `ADV-22` |
| Differential privacy | A benchmark of collection speed across companies: each company contributes one clipped value, the average gets Laplace noise with scale (clip / n) / ε, ε = 1 per release, nothing below five companies; the noise repeats only for identical data, so asking again does not average it away and a changed cohort gets fresh noise. The company sees its own value exactly | `app/services/benchmarks.py` | `tests/test_benchmarks.py`, `ADV-23` |
| Agents with earned autonomy | Agents propose; people decide. Autonomy rises only from the review record, one action and amount limit at a time; L3 money is never delegated | `app/services/review_inbox.py`, `app/stubs/agents.py` | existing tests and evaluation tasks |

## Roadmap, not built

- **Reinforcement learning for collections (contextual bandits).** Learn which reminder timing and tone gets paid soonest, per customer. It needs real outcomes (reminder sent, paid or not, how fast) to learn from. Before the competition it could only learn from made-up outcomes, which would prove nothing, so it is not built. The run history and review decisions already record the events a bandit would need.
- **Federated learning across SMEs.** Train a shared credit or payment-delay model across many companies without pooling their records, in the spirit of WeBank's FATE. It needs several real companies and a training protocol. Today's differential-privacy benchmark is the first step: it shares a noisy aggregate, not records.
